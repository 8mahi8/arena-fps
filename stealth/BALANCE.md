# バランス検証ログ（BOT対戦シミュレーション）

方法: stealth/src/core.mjs をそのまま使い、BOT同士（botHunter / botIntruder、シード付き乱数で目標選択・巡回開始位置にばらつき）を 20Hz で対戦させる（stealth/sim/simulate.mjs）。BOTは最速経路で動くため、人間の試合より短く・荒くなる。数値は「基礎体力の目安」であって実プレイの勝率予測ではない。

## ラウンド1（2026-10-23 初期値: 装置8秒/捕獲0.6秒/ゲート1秒/装置誤って5台配置）
- 30試合: ハンター30勝（全て捕獲）/ 侵入者0勝。平均28→36秒。
- 問題: (1) マップに装置が5台あった（設計は4台）。(2) ゲート操作の累積バグ（毎フレーム進捗リセット）で脱出不能だった。(3) ゲート1秒は追跡下のレースで不利。

## ラウンド2（装置4台に修正、ゲート累積バグ修正、ゲート0.5秒、BOTの逃走・反応遅延・囮捨て判断を追加、マップに抜け道を3か所追加）
- 60試合: ハンター32 / 侵入者28。100試合: **ハンター55勝（全て捕獲）/ 侵入者45勝（全て脱出）**、平均試合28.2秒、平均完了装置1.16台、初装置完了まで平均16.3秒、時間切れ0件。
- 判定: BOT基準では 55:45 で許容帯（40:60〜60:40）に入った。時間切れ勝ちが0件 = タイマーは膠着対策としてのみ機能し、支配的な勝ち筋ではない（健全）。
- 注意: 平均試合時間が短いのはBOTが隠れず最速で動くため。人間同士（隠れる・待つ・様子見）では長くなる想定。実機プレイでの体感（特に「発見=即終了」感と終盤のゲート攻防）が次の検証対象。
- 自動テスト: コア単体テスト 9件 全PASS（到達可能性、同時視認不可、装置の進行保持、通知遅延、ゲート開放条件、捕獲成立/壁越し不可/スポーン保護、時間切れ、壁衝突）。

## ラウンド3（捕獲に正面条件を追加、スポーン向き修正、n=200で再測定）
- 捕獲は「ハンターの正面 約86°以内」でのみ進む仕様を明文化（背後からの理不尽な捕獲防止）。BOT同士では BOT が常時狙うため影響は小さかった。
- スポーン直後の向きが壁向きだった問題を修正（侵入者は南向き、ハンターは北向き）。
- 200試合: **ハンター81勝 / 侵入者119勝（40.5% : 59.5%）**、平均29.4秒、平均完了装置1.32台、時間切れ0件。許容帯の下限付近。BOTは無駄な隠れ・様子見をしないため、人間戦では侵入者の勝率は下がると予想する。現時点ではルール数値は固定し、実機プレイの体感を優先する。
- 補足: n=60程度では軌道のカオス性により ±15pt 程度ぶれる。比較は n≥200 で行うこと。

## 変更履歴（ルール側）
- ゲート操作 1.0秒 → 0.5秒（ラウンド1の捕獲レース常時負けを受けて）。
- マップ開口を3か所追加（装置部屋が袋小路化して捕獲が確定する問題への構造対策）。
